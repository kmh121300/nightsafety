상태: 2026-11-04 정책 확정에 이어 서버·DB·앱 실제 적용과 단위/DB/API·기본 UI 검증까지 완료. [실제 적용 검증](../source/verification/mvp-scoring-2026-11-04/verification.md). 명세 전체/실기기/현장 인수는 별도다. [기능 명세 1.2](night-safety-functional-specification-ko.md), [로드맵](../ROADMAP.md)을 함께 따른다.

## 결정과 적용 범위

| 항목 | 확정 기준 |
| --- | --- |
| 적용 지역 | 기존 대학–정왕역 파일럿. 시흥 전체 확대를 이번 정책으로 완료 처리하지 않음 |
| 필수 시설 | CCTV(`cctv`)·비상벨(`emergency_bell`)·보안등(`security_lamp`) |
| 조명 지표 | 확보한 보안등 공공 CSV를 사용. 보안등의 이름과 원천 유형을 보존하며 `smart_lamp`로 바꾸지 않음. Smartstlamp 확보는 MVP 점수 활성화의 선행 조건에서 제외 |
| 자료 기간 | 점수 사용에 고정된 경과일 상한을 두지 않음. 180일·365일 초과만으로 stale/missing 전환하거나 점수·추천을 차단하지 않음 |
| 자료 선택 | 원천별 확인된 최신 배포본을 수동 가져오기하는 기존 흐름 사용. 최신 여부의 확인 근거와 확인일을 기록. 새 자동수집·배포본 감지 기능은 이번 정책의 요구 범위가 아님 |
| 기준일 | 제공기관의 데이터 기준일, 가져온 시각, 최신 배포본 확인일을 구분. 모르는 날짜는 null/미기록이며 다운로드 시각으로 원천 기준일을 대체하지 않음 |
| 화면 명칭 | ‘공공시설 기반 안전지표’. API의 safety_score·average_safety·weak_safety는 프로젝트의 정식 계산 필드로 사용 |
| MVP 시설 안내 | 출처·데이터 기준일을 표시. ‘현재 시설 작동 여부 미확인’과 같은 뜻의 작동 미검증 안내는 사용자 화면에서 제외 |

180일 유지, 365일 연장, 기간 상한 제거를 비교했고 사용자가 제안한 기간 상한 제거를 채택했다. 조명은 Smartstlamp 확보를 기다리는 방식과 확보한 보안등을 사용하는 방식을 비교해 보안등을 채택한다. 미래의 스마트 조명 원천 도입은 별도의 점수 버전으로 검토한다.

## 점수 사용 조건

세 유형의 입력 형식·좌표·중복 ID·제공범위·유형 매핑 검사가 통과하고 graph/facility/scoring/routing 버전과 평가 구간이 일치하면 정식 점수를 계산한다. 자료의 경과일과 현장 작동 확인 여부는 MVP 점수 활성화의 차단 조건으로 사용하지 않는다. 내부 operational_status/accessibility의 unknown과 기존 현장 검증 기록은 보존한다.

자료 형식 오류·비유한 좌표·ID 충돌·범위 부족·필수 원천 미확보는 계속 검사한다. 누락을 0건으로 처리하지 않으며, 필수 유형이 빠지면 정식 점수는 null이고 공통 부분 지표를 별도로 제공한다. 정상 수집된 원천에 특정 경로 인근 시설이 없으면 그 유형의 영향은 0이다. 기준일 누락은 추정값으로 채우지 않고 표시하되 날짜만으로 점수를 차단하지 않는다.

새 자료 수집·검증이 실패하면 마지막 정상 snapshot과 활성 bundle을 유지하고 실패 상태를 공개한다. 마지막 정상 자료의 실제 범위·형식·버전으로 계산 가능하면 나이 때문에 점수를 null로 만들지 않는다. 기존 자료도 없거나 계산 불가능하면 부분/미확보 상태를 반환한다. `stale`은 과거 정책의 snapshot을 읽는 경우를 위해 구분할 수 있으나 새 MVP 정책의 날짜 기반 차단 상태로 생성하지 않는다.

자료 기간 상한 제거는 버전 보존기간, 페이지 cursor·외부 장소 응답 보관기간, 현재 위치의 시간 초과 정책까지 없애는 변경이 아니다.

## 유지하는 계산·표시 계약

- 기존 거리 kernel 20/50/100m, 유형별 최대 기여, 20m 이하 구간·5m 이하 표본, 길이 가중 평균·하위10% 길이·취약 가중치0.30을 유지한다.
- 후속 구현의 초기 가중치는 기존 동일 가중치1:1:1, 접근/작동 정보 unknown의 기존 실험 기여계수0.5를 세 유형에 동일하게 적용한다. 이는 현재 코드/설정에서 이어받는 초기 모델이며 별도 계수 조정 작업은 하지 않는다.
- 같은 좌표의 여러 보안등 행은 원본과 raw 개수에 보존하되 유형별 최대 기여로 점수에 반복 합산하지 않는다. 행 수를 고유 설치지점 수로 표시하지 않는다.
- 거리0은 점수 null, 실제 연결 없는 요청은 incomplete/no_route 계약을 유지한다. 시설 점수 계산 완료와 보행 경로 연결 완료는 별도 상태다.
- 시설 작동 안내 문구 제외는 출발·도착 간격, 경로 미완결, 누락 자료, 요청 실패, 저장된 과거 결과 안내를 없애는 변경이 아니다.

## 적용·검증 기준

| 대상 | 필요한 결과 |
| --- | --- |
| 수집·정제 | 보안등을 security_lamp로 점수 대상에 연결, 기존 CCTV/비상벨 제외 규칙과 원본 ID·좌표 공유 기록 보존 |
| 계산·탐색 | 3유형 구간·평균·취약·전체 지표와 fast/safe/balanced 선택 계산. 동일 후보/버전 기준 유지 |
| 버전·DB | 새 scoring/routing 설정과 점수 bundle 생성·저장·복원. 구버전 점수/즐겨찾기를 새 지표로 조용히 덮어쓰지 않음 |
| API·앱 | source 상태와 점수 필드·구간 등급·이유·출처·기준일·비교 화면 일치. 작동 미확인 문구 제외 |
| 회귀 | 180/365일을 넘긴 동일 자료의 계산 유지, 보안등 ready/미확보/정상0건, 자료 오류, 갱신 실패, 버전 전환·과거 저장 결과, UI 표시 검사 |

정책 확정은 새 점수 구현·명세 전체 인수·실기기·현장·배포 완료를 의미하지 않는다. 기존 검증은 당시 정책과 APK의 결과로 보존한다.
