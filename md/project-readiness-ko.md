**초기 조사 보고서의 기준본입니다.** 아래 개발 순서·미실행 표기는 2026-10-05 당시 기록으로 보존합니다. 현재 Android/DB 구현·검증 상태와 갱신된 전체 단계는 [전체 로드맵](../ROADMAP.md)을 확인합니다. 2026-10-26에는 문서 안내만 추가했으며 원천 조사나 테스트를 재실행하지 않았습니다.

2026년 10월 5일 점검. **파일럿과 앱 개발은 진행 가능하다. 실제 야간 보행 안내와 완성된 안전점수는 아직 검증되지 않았다.** 먼저 한국공학대학교–정왕역 주변으로 범위를 고정하고, 시설 정보와 후보 경로 비교를 구현하는 것이 현재 데이터에 맞는다.

확인 범위는 제안서 초안, 업로드된 시설 CSV 두 개, 실제 OSM 스냅샷, 경로 재현 코드, TMAP 및 Supabase 공식 공개 문서다. 실제 Android 앱 소스·TMAP 키·Supabase 프로젝트 접속 정보가 없어 앱 빌드와 인증된 지도·DB 통합은 실행하지 못했다. 외부 계정을 생성하거나 프로젝트를 배포하지 않았다.

## 시설 데이터 실제 검사

| 데이터 | CSV 행 | 고유 좌표 | 파일럿 범위 행 | 데이터 기준일 |
|---|---:|---:|---:|---|
| CCTV | 2,130 | 2,129 | 270 | 2026-01-20 |
| 비상벨 | 1,851 | 1,841 | 238 | 2026-01-22 |

두 파일은 CP949다. 전 행의 위도·경도는 숫자·유효 범위 검사를 통과했고 관리번호는 파일별로 고유하다. 시흥시의 대략적인 공간 범위 안에 있지만 행정경계와 대조한 전수 검증은 아니다. 동일 좌표 CCTV 추가행 1개, 비상벨 추가행 10개는 검토 대상으로 기록했다. 서로 다른 시설이 같은 좌표에 있을 수 있으므로 원본 행을 임의 삭제하지 않았다. CCTV와 비상벨 사이 정확히 일치하는 좌표는 시 전체 80곳, 파일럿 9곳이다.

CCTV 설치목적은 생활방범 1,805행, 교통단속 163행, 쓰레기단속 106행, 차량방범 56행이다. 총 카메라 대수 7,647대는 설치지점 수가 아니다. 우선 생활방범을 별도 지표로 쓰고 다른 목적은 지도에 구분 표시한다. 촬영 방향·사각지대·현재 작동은 좌표로 확인되지 않는다.

비상벨은 화장실 53행, 기타 1,798행이다. 경찰연계유무는 Y 53행·N 1,798행이며, 최종점검결과구분은 모두 Y다. 점검일은 2025-12-31 1,798행, 2026-01-22 39행, 2026-01-15 14행이다. N을 고장으로 해석하거나 Y를 현재 작동 확인으로 해석하지 않는다. 화장실 내부 위치·개방시간과 ‘기타’ 시설의 실제 보행자 접근성을 확인해야 한다. 업로드 날짜나 갱신시점으로 데이터 기준일을 대체하지 않는다.

원본 OSM에 옥구지구대 node368606165, 시화파출소 node4636798530, 정왕지구대 building way545484505가 있다. 점 두 개와 건물 polygon을 조사용 GeoJSON에 원본 형태로 포함했다. 건물 중심을 실제 출입구로 만들거나 경찰 도착시간으로 환산하지 않았다. street_lamp 객체는 이 스냅샷에 0개이며 이는 실제 가로등이 없다는 뜻이 아니다.

가로등의 공식 대안 중 경기도 ‘가로등 집계 현황’은 시군별 수량이라 개별 경로 분석용 좌표가 아니다. 생활안전지도 가로등 API는 인증키가 필요한 WMS 이미지 예제를 제공한다. 이미지를 raw 좌표 데이터로 취급하지 않는다. Smartstlamp API는 시흥 필터 포함·미포함 요청 모두 502였고 정상 응답 schema를 확보하지 못했다. 다른 미인증 API가 정상이라고 추정하지 않는다.

## 실제 경로와 시설 좌표를 함께 계산한 결과

기존 미완료 경로의 원본 간선에 대해 5m 이하 간격의 중점 표본을 거리로 가중했다. 아래는 **생활방범 CCTV 또는 화장실 유형을 제외한 비상벨과 직선 50m 이내인 길이 비율**이다. ‘기타’ 비상벨 접근성은 미검증이다. 벽·차도·시야·작동을 반영하지 않는 실험 지표이며 실제 보호 범위나 안전확률이 아니다. 반경 25·50·100m 민감도 결과도 JSON에 있다.

| 후보 정책 | 그래프 거리 | 전용 보행선 비율 | 생활방범 CCTV 근접 비율 | 비상벨 근접 비율 |
|---|---:|---:|---:|---:|
| 거리 우선 | 1,572.40m | 0.17% | 30.85% | 30.85% |
| 중간 보행선 우선 | 1,812.84m | 65.54% | 47.50% | 47.50% |
| 보행선 우선 | 1,932.56m | 76.40% | 45.04% | 45.04% |
| 주요도로 제한 | 1,579.26m | 12.50% | 32.33% | 32.33% |

보행선 비중이 가장 큰 경로가 시설 근접 비율까지 가장 큰 것은 아니다. CCTV와 비상벨 지표도 이번 경로에서는 매우 비슷해 독립적인 위험 감소 효과로 해석할 수 없다. 미확보 가로등을 0점 또는 만점으로 대체하거나 가중치를 조용히 재정규화하지 않는다. 현재 최종 안전점수는 null이다. MVP는 거리·추정시간·보행선 비율·시설 근접 비율·데이터 누락을 먼저 각각 보여준다.

## 경로 설계에서 바꿔야 할 부분

캠퍼스 경계를 통과하는 기존 highway 주변 출발점 7개와 내부 출발점 1개를 사용했다. 이 7개를 공식 출입문으로 확정하지 않았다. 도착점은 역 주변 highway node 3개와 실제 출구 node 2개다. 5개 정책으로 40쌍씩 정·역방향 총400번 탐색했다. 기본 추론 그래프·주요도로 제한·계단/bridge 태그 제외는 각각 정방향24/40·역방향24/40 도달했다. 명시 보행선/foot 허용만 쓰면0/40이다. 실제 출구 1·2에 대해서는 출발점8개×출구2개 모두 연결되지 않았다.

원본 연속 node 간선만 사용했고 도달한 정방향의 A* 비용은 Dijkstra와 일치했다. 거리만으로 최근접 node를 이어 붙이지 않았다. 출구1까지 12.56m 간격, 보행선 우선 후보의 도로 선형 456.08m, 옆문 운영·육교·횡단이 남아 있다. 정확한 출구까지의 완료 경로는 null이고 검증 필요 상태를 유지해야 한다.

거리순 Yen K=30은 1,572.40~1,591.62m에 몰려 1,932.56m 보행선 우선 후보를 포함하지 못했다. 따라서 ‘최단 K=3 생성 → 안전점수 재정렬’은 수정한다. 거리·보행선·검증된 접근권 등 여러 정책에서 후보를 생성해 합친 후 중복과 공유 간선 비율을 검사한다. 그 뒤 시간 상한을 적용하고 시설 지표로 비교한다. 유효 후보가 부족하면 실제 개수만 반환한다.

1.2m/s 가정에서 +10분은 +720m이며 보행선 우선 후보는 최단보다 약 +5분이다. 이 시간은 신호대기·경사·개인 속도를 반영한 실측 ETA가 아니다. edge 비용은 거리에 비음수 페널티를 더하는 형태로 유지한다. 경로 전체의 평균·최악 구간·시설 중복 제거처럼 비선형인 지표를 단순 A*로 전역 최적화했다고 주장하지 않는다. 세부 결과는 routing/route-readiness.md에 있다.

## 지도와 서버를 연결할 설계

Kotlin 화면은 TMAP 지도에 자체 OSM 경로 및 공공시설을 overlay하고 비회원 즐겨찾기는 Room으로 저장한다. 서버는 허용 지역과 요청 크기를 제한한 경로 endpoint를 제공하고 PostGIS 시설 조회와 pgRouting 계산을 담당한다. 앱에 DB 비밀번호나 Supabase secret/service_role을 넣지 않는다. 공개 조회에 쓸 publishable key도 grants/RLS 및 RPC 범위를 적용한다.

TMAP 보행 옵션은 0 추천, 4 추천+대로우선, 10 최단, 30 최단거리+계단제외다. ‘최속’ 또는 ‘안전 최적화’ 제공으로 이름 붙이지 않는다. 경위도 REST의 X는 경도, Y는 위도다. GeoJSON/DB는 longitude,latitude로 통일하되 구 Raster와 Vector Android SDK의 함수 인자 순서가 다르므로 adapter에서 처리한다.

TMAP 공식 간단 약관에 데이터 저장 후24시간 이상 사용 제한이 있다. TMAP POI·경로 응답을 영구 축적하는 즐겨찾기 설계는 변경한다. 사용자 직접 지정 장소나 이용조건이 확인된 별도 공공/OSM 자료를 저장하고 TMAP 응답에는 만료를 둔다. 자체 OSM overlay의 기술적 지원은 확인됐지만 구체 배포 조건과 TMAP 반환 장소값의 장기 보존 범위는 공급자 확인이 필요하다.

TMAP 무료 일 한도는 지도100,000건, POI20,000건, 지오코딩20,000건, 경로안내 그룹1,000건이다. 경로 옵션 세 개를 별도 호출하면 한 검색에 세 건이 될 수 있다. Supabase Free는 DB500MB·파일1GB·egress5GB와cached egress5GB, 비활동1주 후 pause다. 현재 raw OSM7.9MB만으로 DB 용량을 보장하지 말고 테이블·geometry·인덱스·로그까지 import 후 측정한다.

DB는 Dijkstra를 기준으로 시작하고 실제 설치 pgRouting의 버전·schema·overload를 읽은 뒤 KSP를 붙인다. 공개 upstream 버전과 hosted DB 버전이 같다고 가정하지 않는다. 좌표 degree와 미터 비용을 섞은 A* heuristic도 그대로 적용하지 않는다. platform/verification.sql은 읽기 전용 준비 파일이며 실제 Supabase에서는 아직 실행하지 않았다. 자세한 비용·한도·키·SDK 검토는 platform/platform-readiness.md에 있다.

| 8 | 조명·경찰 공식 자료와 점수 기준 확보 후 범위 확대 | 출처·이용조건·기준일·누락 정책, 파일럿 외 OD·용량·성능 검증 |

초기 위치권한은 사용자 시작점 입력에 필요한 범위로 제한한다. 백그라운드 추적·실시간 위치공유·긴급 관제는 제안서 핵심 구현과 별도로 결정할 기능이다. Android 실제 permission·네트워크·SDK 호환 동작은 코드가 생긴 뒤 기기에서 검증한다. DB timeout/rate limit와 시흥 bbox·거리·K 상한을 적용한다.

공공 CSV의 원 다운로드 페이지 및 재사용 조건은 파일 내용만으로 확인되지 않으므로 메타데이터에 확보해야 한다. OSM은 OpenStreetMap 기여자 표기와 ODbL 조건을 따른다. 배포 시 출처 표기와 선택 SDK의 로고 표시를 유지한다.

## 재현과 증거

압축파일에는 이 보고서, 영역별 보고서, 데이터 감사 코드·결과, 준비 SQL, 원본 CSV/제안서 및 실행에 필요한 OSM V2 입력·코드가 있다. 앱 완성본은 아니다.

압축을 풀고 Python에 SciPy가 있는 환경에서 실행한다. audit_routing.py는 표준 라이브러리와 동봉 PoC를 사용한다.

```bash
python project_readiness/data/audit_facilities.py
python project_readiness/routing/audit_routing.py
python -m unittest discover -s osm_poc_v2 -p 'test*.py' -v
```

실제 재실행 결과: 기존 테스트16개 통과, 시설 행수·좌표·중복·반경 민감도 검사 통과, 라우팅400번 탐색 및 Yen30개 원본 간선·loopless·거리정렬 검사 통과. Android 빌드·인증 API·Supabase SQL 실행·현장 보행은 여기에 포함되지 않는다.
