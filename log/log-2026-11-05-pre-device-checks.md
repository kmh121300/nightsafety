# 실기기 연결 전 MVP 검사 순서

작성일: 2026-11-05 · 최종 수정일: 2026-11-06 · 시간 기준: Asia/Seoul

사용자는 실제 휴대폰을 연결하기 전에 기기 없이 할 수 있는 준비를 마치기를 원했다. 기존 MVP 범위를 기준으로 아래 순서를 우선한다. 최초 작성은 검사 순서 정리였으며 이후 실제 완료 결과는 아래 날짜별 진행에 별도로 기록한다.

1. **최신 APK 전체 기능 흐름 확인.** 검색/후보 비교/구간/필터와 Room 저장·재시작·오프라인 복원·이름/선호유형 수정·재조회·삭제. 기존 전체 UI8개는 이전 APK 근거다. 최근 고정 글꼴 APK의 정상→0거리는 이미 통과했으므로 변경 영향이 없으면 별도 반복하지 않는다. 실행 환경은 현재 준비된 API35 서버/에뮬레이터를 먼저 재사용하고 설치 완료/해시를 확인한 뒤 종속 검사를 시작한다.
2. **오류·복구 및 권한 모의 검사.** 잘못된 좌표/빈 검색, 출발·도착 교환, 서버 연결 끊김/재연결, 최신 결과와 이전 결과 구분, 앱 종료/재실행 시 저장 결과·입력 처리. 에뮬레이터에서 가능한 위치 권한 거부·시간 초과/모의 위치 흐름을 확인한다. 기기 설정을 바꾸면 원래 값으로 복원한다. 실제 GPS 수신/정확도를 검증한 것으로 간주하지 않는다.
3. **실패 원인 분리와 명세 대조.** API36.1의 앱 화면 소실은 아직 원인 미확정이다. 시스템/런처 지연과 실제 앱 오류를 구분해 동일 APK 재현 근거를 확보한다. 기존 기능 명세의 필수 항목과 구현/검사 근거를 대조해 미검증과 미구현을 구분하고 MVP의 필수 누락만 보완한다. 기기 전용 차이는 실기기 검사표로 이관하며 미해결을 성공으로 바꾸지 않는다. 사용자 선택의 세로/글꼴 배율 고정을 취소하거나 시흥 전체·운영 배포를 자동 추가하지 않는다.
4. **에뮬레이터 UI 확인과 설치 준비.** 작은 화면에서 버튼·본문·스크롤·빈 상태/오류 상태를 확인하고, 검사된 APK·해시·서버 실행/USB reverse 절차·실기기 검사표를 묶는다. 사용자 최종 디자인 판단은 요청대로 나중에 직접 한다. 검사 중 앱을 수정했다면 영향을 받는 범위만 재검증한다.

위 작업 뒤에 실제 기기를 연결해 GPS 수신·실제 OS 권한·제조사별 화면/터치/성능을 확인한다. 현장 보행/통행·운영 배포 검증은 별도 미완료다. ViewBinding 전환은 논의만 했고 구현 지시가 없으므로 이 필수 검사 순서에 자동으로 포함하지 않는다.

이번 작업은 우선순위 기록만 변경했다. 앱/서버/DB/APK 변경 및 새 빌드/테스트 실행 없음. 담당자·완료일을 새로 정하지 않았다. [로드맵](../ROADMAP.md), [0거리 완료](../source/verification/android-2026-11-05_210638_044884/verification.md), [기능 명세](../md/night-safety-functional-specification-ko.md).
