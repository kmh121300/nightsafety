# R4 보안등 추가본의 DB 기반 전체 UI 재검사

작성일: 2026-11-03 · 최종 수정일: 2026-11-03 · 시간 기준: Asia/Seoul

## 범위와 환경

사용자가 최신 DB와 보안등 추가 APK의 전체 UI 재검사 진행을 승인했다. Windows, 프로젝트 Python3.10.11/JDK21.0.11, Pixel_3a Android15 API35, emulator-5556을 사용했다. 기존 AVD 자료를 보존하고 TEMP의 별도 사용자 이미지·headless SwiftShader·3072MB·no-snapshot으로 실행했다. SDK 접근/외부 DB 접속은 권한 확장 실행이 필요했다.

`source`에서 `.\.venv\Scripts\python.exe -X utf8 server/app.py`로 실제 DB 서버를 시작했다. `/health`의 configured=true/verified=true, safenight/startup_snapshot과 시설 API1,378행을 확인했다. DB import·스키마·원본 CSV·점수 정책은 변경하지 않았다.

## 실패와 원인

22:08~22:12 KST 최초 전체 UI 실행은 지도1,381개·기본 후보3개·anchor 검색·취약 구간 상세까지 통과한 후 앱 자체 ANR로 종료코드1이었다. [실패 및 진단](../source/verification/android-2026-11-03_220808_226636/failure.md)을 보존한다. 설치 APK와 로컬 APK 해시 일치도 확인했다.

Android 진단 서비스에서 해당 앱의 ANR 사유와 메인 스레드만 추렸다. MotionEvent5003ms timeout이고 `showWeakSegments → refresh → TmapPilotMap.update → TMapView.addTMapMarkerItem → createMarker`에서 실행 중이었다. 취약 구간 토글마다 전체 시설 마커1,381개를 지우고 다시 생성하던 경로를 확인했다. SDK 키·원본 로그·연결 문자열은 저장하지 않았다. 이전 지도 준비 문구 실패와 원인이 같다고 단정하지 않는다.

## 수정과 회귀 검사

`TmapPilotMap`에서 기존 시설 overlay 목록을 유지하고 ID와 시설 값이 달라진 항목만 제거/추가한다. 경로선·취약 구간·현재 위치 표시 로직과 시설 클릭/상세는 유지한다. 필터는 해당 유형만 제거/복원하며, 같은 ID의 좌표·유형·상세가 바뀌면 기존 overlay를 교체한다. 시설 ID의 고유성 검증은 기존 파서 계약을 따른다.

- 신규 `FacilityOverlayTest`3개: 전체 재생성 동작에서3개 assertion 실패를 확인한 뒤 수정 후 통과.
- `.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --offline --console=plain`: 종료코드0, BUILD SUCCESSFUL. 전체 단위17개·실패0·오류0·skip0, lint 오류0·경고44.
- 수정 APK SHA256: `07115bef4ea8a710aaed9aba6d8e45c7602c3ee047eb5b2ffbf4411b563367fe`.
- main/debug 소스22개 집계 SHA256: `660ef8d5975dc58f63da6c6463fb8a9cd92e1b6377714a094e185e96ea884d03`. 정렬 상대경로(`/` 구분)·NUL·파일 바이트·NUL 순서, 비밀 설정과 생성 BuildConfig 제외.
- 읽기 전용 별도 코드 검토에서 material finding 없음. 최초 전체 표시/대량 필터 복원은 여전히 동기 SDK 작업이므로 실제 UI 재검사와 실기기 검증을 대체하지 않는다.

## 재검사와 남은 범위

수정본 첫 실행22:18~22:24 KST은7개 단계 후 마지막 삭제 목록 확인의 ADB shell 실패로 종료코드1이었다. 직후 device 연결/프로세스/UI dump/read 정상과 삭제 완료 문구를 확인했지만 정확한 ADB 실패 원인은 미확정이다. '전체 목록이 비었음'을 즉시 가정한 별도 후속 assertion도 실패했고, 이를 제품 삭제 실패/성공의 근거로 삼지 않았다. [당시 실패와 후속 관찰](../source/verification/android-2026-11-03_221824_537215/failure.md)을 보존한다.

**최종 재실행22:26:20~22:32:35 KST: 종료코드0, 전체 UI8개 통과.** 지도/시설1,381개·기본 후보3개·anchor/미완결 안내·취약 구간·CCTV/보안등 필터·Room 재시작/서버 연결 제거 후 복원·수정/온라인 재조회·삭제 후 목록 반영을 모두 확인했다. [완료 보고서와 캡처](../source/verification/android-2026-11-03_222620_934204/integration-ui.md). 이 실행에는 앱 ANR이나 외부 System UI ANR 닫기가 없었다. 최초 실패와 ADB 실패를 새 성공으로 덮지 않는다.

최종 두 캡처에서 실제 TMAP 타일·로고·경로·시설·주황 취약 구간과 과거 자료/현장 미검증/공식점수 미산출 안내를 시각 확인했다. 지도 영역(40,350)-(1040,1040)의 주황 RGB(205,85,15) ON1,969/OFF0픽셀 대조도 통과했다. 최종 설치 APK 해시 일치와 DB ready/configured/verified는 같은 수정본의 재검사 전에 확인했다. R4의 최신 DB 기반 기본 UI 통합은 검증 통과로 갱신한다. 실기기 GPS/권한·명세 전체 TC·현장 보행/점등·공식 안전점수·운영 성능과 배포는 이 작업의 통과 범위가 아니다.

검사 후 이번에 시작한 로컬 서버와 임시 에뮬레이터를 종료했다. 기존 AVD와 임시 이미지·검증 증거는 삭제하지 않았다. 로드맵 단계/기능16개·실행 안내·로그·성공/실패 기록의 날짜와 내부 링크, 최신 결과 일치 여부를 최종 대조했다. 서버/DB 구현을 바꾸지 않아 DB import/rollback 검사를 불필요하게 반복하지 않았다.
