## 2026-11-03 15:29~15:31 KST DB 재활성화 후 작업

사용자 재활성화 알림 후 기존 승인 범위의 실제 DB 작업을 재개했다. 제한 환경 접속은 실패했으나 권한 확장 환경의 `server/postgis.py` 읽기 조회는 성공했다. `server/postgis.py --apply` commit 성공: 시설1,378·노드27,607·간선8,208·구간22,256. 이어 `tools/db_smoke.py --verify-import` 종료코드0: 재가져오기 행수 불변, 비정상 도형 시험 import 전체 rollback, 모든 노드/태그·간선·시설/속성·점수 표본/구간/비용 동등성, SRID/도형·RLS·DB 기반 HTTP health/config/facilities/places·경로3개/evaluate/0거리와 공식 점수 null이 통과했다.

## 상태 영향과 남은 범위

- R5는 **시흥 보안등 위치 원본 확보·파일 검사 완료**로 갱신한다. 기존 조명 위치 자료 미확보 상태는 해소됐으나 일반 가로등·스마트가로등 확보/검증을 뜻하지 않는다. 파일명과 실제 컬럼은 보안등이며 스마트 기능을 증명하는 컬럼은 없다.
- 2026-11-03 기준 자료 기준일로부터 252일 경과했다. 현재 서버의 180일 정책과 비교하면 오래된 자료이므로 다운로드 사실만으로 현재 유효 자료/공식 점수 사용 가능으로 바꾸지 않는다.
- 반영 전 좌표 누락 격리, 중복/고유 ID 정책, 시설 유형 매핑과 명세의 스마트가로등 요구 충족 여부, 출처·이용조건·전수 범위 확인이 필요하다. 확정한 점수 정책 변경은 없다.
- 실제 시흥 경계 포함 여부의 공간 검증, 현장 위치 정확도·점등/고장·야간 접근성·조도는 미검증이다. 시흥 주소와 전역 위경도 범위 통과가 현장 검증을 대신하지 않는다.
- 이번 요청은 파일 확인 범위다. 앱/서버 코드·CSV 원본·DB를 변경하지 않았으며 import, 앱 빌드, DB/API 검사는 실행하지 않았다. 기존 공식 점수 null과 앱/DB 검증 상태는 유지한다.

## 2026-11-03 후속 구현과 검증

사용자가 데이터 정리·서버/DB/지도 연결 진행을 승인했고, [경기데이터드림 원본 페이지](https://data.gg.go.kr/portal/data/service/selectServicePage.do?infId=VEY71398U2941WM4E7PV21507518&infSeq=1)를 다운로드 출처로 제공했다. 위 절의 '이번 요청은 파일 확인 범위'는 최초 검사 당시 범위이며 이 후속 작업과 구분한다.

- [계획](../source/docs/superpowers/plans/2026-11-03-security-lights.md)에 따라 별도 보안등 asset과 감사 JSON 생성, 서버 `security_lamp`/앱 `lamp` 표시·필터·상세를 구현했다. 원본 CSV와 기존 시설 asset은 수정하지 않았다.
- 공유 좌표의 행을 삭제하지 않고 snapshot 해시/레코드 번호 ID와 공유 개수를 보존했다. 좌표 누락53행은 격리 기록, 파일럿 밖8,342행은 범위 제외 기록으로 남긴다.
- 보안등은 표시 전용이다. 기존 점수 grid·공통 CCTV/비상벨 기준과 공식 점수 null 정책은 유지했다. 스마트가로등 확보나 공식 지표 인수를 뜻하지 않는다.
- 최종 서버18개·도구5개·Android14개 통과, lint 오류0/경고44, APK 빌드와 포함 asset 일치 확인. 보안등 없는 baseline과 모든 간선 비용·점수 표본·구간·토폴로지 동일 대조도 통과했다. 날짜·환경·명령·APK 해시는 [검증 보고서](../source/verification/security-lights-2026-11-03/verification.md)에 기록했다.
- 실제 DB 조회는 권한 확장 후에도 `tenant/user not found`로 실패했다. DB 신규 쓰기는 실행하지 않았으며 사용자에게 Supabase 프로젝트 상태/로컬 연결 정보 확인을 요청했다. 연결 정보를 채팅으로 받지 않는다.
- 에뮬레이터 UI 검사는 로컬 파일 엔진을 명시적으로 사용한다. 실패한 DB 설정을 자동 fallback으로 우회하는 제품 변경은 없다.
