# 작은 화면 점검과 설치 준비 검증

작성일: 2026-11-06 · 최종 수정일: 2026-11-06 · 검증일: 2026-11-06 · 시간 기준: Asia/Seoul

사전 검사4번의 지정 화면 검사와 설치 자료 준비 완료. 실제 휴대폰 GPS·제조사 동작·사용자 최종 UI 판단/명세 전체 인수 완료와 구분한다.

## 대상과 결과

Windows/JDK21, Pixel_3a 임시 read-only AVD/API35/emulator-5556. DB startup_snapshot 서버를 다시 기동했다. 앱은 세로/글꼴1.0 고정 정책을 유지했다. 최종 APK SHA256 `b863ec3a3387d83c66ee59bfba7f85d58fea52ddb7d781e81734660385b1f0e6`.

[실행 결과](../android-2026-11-06_101527_916705/screen-result.json): 종료0·3개 검사 묶음 통과, 지도 버튼 geometry7상태 확인, cleanup_errors0. 두 화면은 해상도/밀도 적용 뒤 앱을 새로 시작해 검사했으며 창 크기 변경의 상태 복원을 고쳤다는 뜻이 아니다.

## 발견과 수정

- 첫 시도는 외부 Pixel Launcher 응답 지연 창으로 중단. [원시 결과](../android-2026-11-06_100121_899156/small-preflight.json)와 [복원 후 창](../android-2026-11-06_100121_899156/after-restore.png)을 보존했다. 실제 제목 확인 후 Wait만 선택했고 앱 ANR을 무시하도록 바꾸지 않았다.
- [수정 전 작은 화면](../android-2026-11-06_100411_221578/small-initial.png)의 로컬 보기 버튼이48dp 미만으로 잘린 것을 [geometry assert 실패](../android-2026-11-06_100411_221578/screen-result.json)로 재현했다. 작은 높이의 지도에 세로168dp 버튼 묶음이 들어가지 않은 것이 원인이다.
- 기본 map XML은 가로48dp 버튼 행으로 바꾸고, 가용 높이h720dp 이상에는 원래 XML을 그대로 두었다. 두 XML만 앱에서 수정했다. Kotlin/서버/DB·점수 정책·Room schema 변경 없음.
- 수정 APK 첫 [화면 검사](../android-2026-11-06_101106_812471/screen-result.json)는 초기 로드된10회 스크롤 도구의 탐색 한계로 data_info에서 중단됐다. 깊은 항목 탐색 회귀 실패 후 최대20회/동일 화면 끝 감지로 도구를 보완했다. 이 실패를 앱 잘림 재발로 분류하지 않는다.

[빌드 기록](build-result.json): lintDebug/assembleDebug 성공, lint 오류0/경고33. 도구13개 통과. Kotlin compile은 UP-TO-DATE이고 Android27개 단위 검사는11월5일 당시 근거로 보존했다. 이번 XML 변경에 재실행했다고 쓰지 않는다. DB 가져오기/서버 회귀는 무관한 범위여서 반복하지 않았다.

## 설치 묶음과 잔여 범위

[검증 APK·SHA256 묶음](../../delivery/2026-11-06/README.md), [USB 설치/실기기 검사표](../../DEVICE-TEST.md)를 준비했다. 원본/설치본/복사본 SHA256 일치 확인. 기존 실행법.md의 PowerShell 호출 연산자/대상 선택·버튼 위치·시설지표의 실제 위험 단정 표현도 바로잡았다.

실기기 GPS·실제 대략 위치 정확도·제조사별 화면/터치/성능·사용자 최종 UI·현장 보행·운영 배포는 미검증이다. 과거 API36.1 소실 원인은 미확정이고, 지도 pin/viewport 재조회 등 [명세 차이](../spec-audit-2026-11-05/functional-matrix.md)도 남는다. 이번 결과를 전체 명세 인수 완료로 확대하지 않는다. ViewBinding 전환·새 기능 확장은 하지 않았다.
