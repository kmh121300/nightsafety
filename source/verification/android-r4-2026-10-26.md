- APK SHA256: `dd91a5167f6e060abb426f126c9ae74ccf6c86a2dea4c7769f706995bbda7927`.
- 2026-10-27 확인한 app/src의 main/debug20개 파일 집계 SHA256: `7902ec95452aad7c2c246aae0affb9f4b35bc454a5c4435665593cc9a1c81729`. 정렬된 상대 경로, NUL, 파일 바이트, NUL을 순서대로 해시. 비밀 설정/생성 BuildConfig는 집계하지 않음.

## 빌드와 단위 검사

2026-10-26 실행:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --console=plain
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug --rerun-tasks --console=plain
```

첫 검사는 BUILD SUCCESSFUL(1분29초), lint 오류0·경고49개. 두 번째는 캐시 결과를 재사용하지 않도록45개 작업을 실제 실행했고 BUILD SUCCESSFUL(1분58초). XML 결과에서 Android 단위14개·실패0·오류0 확인. 새로 생성한 APK를 에뮬레이터에 설치했다. 기본 sandbox에서 Gradle wrapper의 네트워크 접근은 차단됐고, 승인된 확장 환경에서 위 검사들을 실행했다.

## 검사 도구와 과거 기록 보존

UI 도구가 고정 파일명의 보고서/캡처를 덮어쓰는 것을 임시 디렉터리의 회귀 테스트2개로 재현했다. 두 테스트의 실패를 확인한 뒤 날짜·시각·마이크로초별 출력 폴더로 바꿨다. 수정 후2개 통과. 새 보고서는 작성일·수정일·실제 검증 시각·APK 해시를 기록한다. 과거 verification/integration-ui.md와 캡처는 덮어쓰지 않는다.

## UI 검사 상태

2026-10-26 23:57에 시작한 호스트 GPU 실행은 2026-10-27 지도 준비 대기에서 실패했다. 전원은 Awake/IsPowered/StayOn, 부팅완료1, 앱 프로세스 존재를 확인했지만 앱과 Android 홈이 모두 검은 화면이었다. [해당 실행의 실패 기록과 캡처](android-2026-10-26_235713_395139/failure.md)를 보존했다. 정확한 드라이버 원인은 미확정이며 TMAP 결함으로 단정하지 않는다.

화면 설정 복구 후 해당 에뮬레이터를 종료했다. 기존 AVD를 지우지 않고 TEMP의 새 사용자 이미지·소프트웨어 렌더링·3072MB로 별도 실행했다. 홈 화면은 표시됐으나 앱 실행 전부터 System UI 응답 없음이 발생했다. [앱 실행 전 홈 캡처](android-r4-2026-10-27-home-systemui.png)를 보존한다. 해당 환경에서도 같은 새 APK의 TMAP 준비/시설511개 및 기본 서버 검색 후보3개 검사가 이후 통과했고, 이어 아래 전체8개 흐름을 완료했다.

2026-10-27 실패 보고서의 날짜·관찰 상태를 자동 보존하는 회귀1개를 추가했다. 실패 재현 후 보완했고 증거 보존 회귀는 총3개 통과했다. 별도 코드 검토에서 차단 문제는 없었다. 생성 보고서의 해시는 로컬 APK를 대상으로 하므로 후속으로 설치된 APK의 바이트도 읽어 비교했고, 같은 SHA256임을 독립 확인했다.

새 임시 환경의 후속 전체 검사에서 아래8개 흐름이 모두 통과했다. 실행 도구 종료코드0, 완료 시각은 **2026-10-27 00:34:45 KST**이다. [전체 결과](android-2026-10-27_001901_382784/integration-ui.md)를 확인한다.

1. TMAP 지도 준비·시설511개.
2. 기본 검색 후보3개·미완결/과거자료/공식점수null 안내.
3. OSM anchor 검색·그래프 연결과 실제 보행 미검증 구분.
4. 과거 하위10% 구간 상세·주황 overlay ON/OFF.
5. 시설 필터511→241→511.
6. Room 저장·앱 강제종료/재시작·서버 연결 제거 상태의 오프라인 복원.
7. 이름/선호유형 수정·온라인 재조회에서 보행선 우선 선택.
8. 삭제 후 목록 반영.

[주황 표시 캡처](android-2026-10-27_001901_382784/integration-weak-tmap.png)와 [필터 복원 캡처](android-2026-10-27_001901_382784/integration-tmap.png)를 직접 시각 확인했다. TMAP 타일·경로선·시설·로고·과거 자료/실제 보행 미검증 안내가 표시된다. 지도 영역(40,350)-(1040,1040)의 RGB(205,85,15) 픽셀은 ON2039개/OFF0개로 실제 overlay 제거도 확인했다.

결론: 현재 소스의 앱 기본 흐름은 위 시험 환경에서 검증됐다. 앱 동작 코드를 수정하지 않고 새 시험 환경에서 통과했으므로, 기존 실패를 SDK/앱 결함으로 확정하거나 특정 GPU 드라이버 수정으로 해결했다고 주장하지 않는다. 모든 인수 TC·성능 목표·실기기·현장 보행을 통과했다는 뜻은 아니다.

실기기 GPS와 실제 위치 권한 흐름은 실기기가 연결되기 전까지 통과로 기록하지 않는다.

## 정리와 남은 작업

2026-10-27 검사에 사용한 임시 에뮬레이터를 종료했다. 이전 AVD의 화면 유지 설정은 복구했고 원래 사용자 자료는 삭제하지 않았다. DB health는 마지막에도 ready/configured=true/verified=true/safenight/startup_snapshot이었다. 다음은 USB 디버깅으로 실제 Android 휴대폰을 연결한 뒤 GPS·위치 권한·수동 입력 유지 흐름을 확인하는 작업이다.
