# 경로 표시 가독성 개선 계획

작성일: 2026-11-07 · 최종 수정일: 2026-11-07 · 시간 기준: Asia/Seoul

사용자가 제안한 선택 경로 강조·후보 흐리기·출발/도착 핀·시설 밀도 낮추기를 승인했다. 같은 TMAP/로컬 미리보기와 ViewBinding/점수 계약을 유지한다. 선형 좌표를 바꾸거나 미완결 연결선을 만들지 않는다.

- [x] 공통100m 표시 필터/캐시·요청 endpoint 유지/0거리 핀의 단위4개를 먼저 작성해 미구현 참조 실패를 확인하고 구현 후 통과한다.
- [x] 선택 경로는 흰 테두리 파란 선, 후보는 옅은 회색, 등급/취약은 선택 선 안쪽으로 표시한다. 두 지도 렌더러 모두 같은 표시 범위를 사용한다.
- [x] 출발/도착 라벨 핀을 SDK/로컬 지도에 표시한다. 도착 핀은 요청 위치이며 미완결 구간은 기존 안내로 남긴다. 0거리/경로 없음의 이전 표시도 지운다.
- [x] 지도/시설 목록은 선택 경로100m 주변으로 제한하고 보유 필터 기록 수와 지도 표시 수를 따로 적는다. 점수/서버 시설 수는 변경하지 않는다. 필터·선택 변경 시 기존 오버레이 diff/배치 큐를 유지한다.
- [x] 빌드/전체 단위/lint/도구 및 실제 SDK/로컬 캡처·선택/필터/전체화면 회귀를 확인한다.
- [x] 새 APK/해시·날짜별 검증·ROADMAP/로그/설치 안내를 갱신한다. 실제 경로 정합성/현장 검증은 별도다.

100m는 지도 표시만을 위한 구현 선택이다. polygon은 경로와의 교차/내부/경계거리도 고려한다. 좌표 계산은 기존 파일럿 범위의 근사 평면이며 서버 지표 계산에 사용하지 않는다. SDK 외부 라이브러리 추가 없음.

추가 표시 보완: 선택/검색/지도 가용 영역 변경 시 SDK fitBounds+Insets로 경로/핀을 맞춘다. 짧은 화면은 전체 지도 여백으로 fallback하며 fullscreen에서 카드 없이 확인한다. 필터/취약 토글 자체에는 카메라 재맞춤을 하지 않는다.
