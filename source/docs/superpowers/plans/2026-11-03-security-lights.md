# 보안등 파일럿 연결 계획

작성일: 2026-11-03 · 최종 수정일: 2026-11-03 · 시간 기준: Asia/Seoul

사용자가 승인한 다음 작업은 보안등 데이터 정리와 기존 서버·DB·지도 연결이다. 기존 Python/PostGIS와 Kotlin/XML 구조를 사용한다. 보안등은 `security_lamp`/앱 `lamp` 유형으로 표시하며 명세의 `smart_lamp`로 간주하지 않는다. 기존 CCTV·비상벨 점수 기준, 공식 점수 null, 파일럿 서비스 범위를 유지한다.

## 설계와 범위

기존 시설 파일에 덧쓰기보다 별도 생성 GeoJSON을 기존 로더에 결합한다. 원본 CSV와 과거 산출물을 보존하고 재생성이 가능하다. 원본 SHA256+CSV 행 번호로 snapshot 내 고유 ID를 만들며 행 순서 변경은 새 snapshot으로 다룬다. 좌표 누락/비정상 및 범위 밖 행은 감사 결과에 남긴다. 같은 좌표의 행은 삭제하지 않고 공유 개수를 표시한다. 전체 원문 속성·기준일·출처 URL을 보존한다. 제공 범위와 최신 점등 상태는 추정하지 않는다.

## 실행 순서

1. importer 테스트를 먼저 실패시킨 뒤 표준 라이브러리 CSV 검사/파일럿 추출, 감사 JSON, 별도 GeoJSON 생성을 구현한다. 누락·비유한값·범위 밖·날짜 오류·이름/좌표 중복·재현성을 검사한다.
2. 서버/API 테스트를 먼저 실패시킨 뒤 marker-only 보안등을 연결한다. 시설 버전에 새 파일 해시를 포함한다. DB는 기존 append-only bundle import와 hydrate를 그대로 사용하며 신규 bundle과 전체 동등성·재가져오기/rollback을 검증한다.
3. Android 파서 테스트를 먼저 실패시킨 뒤 별도 asset 결합, 보안등 필터·색·상세와 기준일 안내를 연결한다. 기존 필터/지도·저장 흐름의 검사 기대 행수를 갱신한다.
4. 서버/도구 단위 검사, Android 단위·lint·APK 빌드, 가능한 DB/API·에뮬레이터 검사를 실행한다. 결과와 미검증 범위를 날짜별 로그·로드맵·실행 안내에 기록한다.

## 검토 중점

- 같은 이름/좌표를 가진 복수 행의 유실과 ID 충돌 방지.
- 누락·NaN·Infinity·범위 밖 좌표를 마커로 내보내지 않음.
- 날짜 형식 오류는 실패시켜 잘못된 정상 자료 배포를 방지.
- 보안등만 추가해도 기존 점수·경로 비용은 달라지지 않음.
- 이전 DB bundle은 보존하고 실패한 import는 전체 rollback.
